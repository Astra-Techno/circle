# CIRCLE UI audit — 30 October 2026

Reviewed source: `1f94998` on main, after the immersive navigation/header fix. This is an audit, not a new app release. No production UI code changed in this audit.

## Scope and evidence

Inventoried 46 feature presentation files plus shared components, themes and router/shell. Reviewed the reachable screen families and their loading/error, form, navigation, media and permission patterns. Components are not counted as individual pages. Hidden Albums/Activity are identified separately rather than described as released features.

Evidence labels: **Reproduced** = temporary widget test with fictional server responses; **Source** = control flow directly visible in code; **Device report** = owner's screenshot, not reproduced against production here. Recommendations do not imply that every page was manually exercised on an iPhone.

The preceding implementation generated nine Home/Groups/You renders at393px/light/100%,320px/dark/200%,900px/dark/200%; samples are in design-previews/immersive-ui. Header tests exercise one Chats title/create action and down/up behavior; live chat/event tests cover populated phone/tablet/light/dark/large-text screens. Physical VoiceOver/TalkBack, iOS keyboard/gallery handoff and actual production image responses remain unverified. The execution proxy denies production-domain CONNECT403, which is not a server diagnosis.

## Visual polish recommendations (not confirmed functional defects)

1. Use one screen hierarchy: route title, section heading, body/meta; avoid decorative intro panels on utility screens.
2. Standardize row density, avatar sizes and metadata treatment across inbox/member/search/session lists. Keep photos visually dominant when they load; do not substitute decorative gradients for real media.
3. Use shared loading/error/empty components with contextual recovery, not identical large cards on every page.
4. Review real-device light/dark contrast, VoiceOver order, dynamic type and reduced motion. Current large-text tests establish layout behavior, not a complete accessibility certification.
5. Consider photo crop/reposition and a consistent media-viewer background/controls after reliable delivery. These are design/feature choices, not repairs proven by this audit.

## Fix order and completion criteria

1. **Recovery and trust:** UI01–05. Network failure never looks like indefinite loading; edits survive or warn; iOS never advertises an unsupported primary action; actual private photos load on the phone.
2. **Navigation consistency:** UI06–08. Route-specific titles, focused editors/viewers and stable loading/error chrome. Verify single headings, Back/swipe-back and down/up navigation on all root tabs.
3. **Profiles and forms:** UI09,11–12. Honest complete/subset states, inline validation and reachable Save actions. Backend additions, if chosen, require an API contract and authorization coverage.
4. **Polish:** UI10,13–14 and visual recommendations. Remove scaffolding from normal flows, simplify invitations and connection states while retaining Copy link, privacy controls and accessible actions.
5. **Release acceptance:** review phone/tablet light/dark/100–200% renders and real native keyboards/pickers. Resolve actual Windows CI test failures and review intentional Windows goldens; never regenerate Linux baselines just to hide differences. Publish a new immutable APK/incremented build and a new TestFlight build only after the implementation batch is verified.
