# Password change and active devices

27 October 2026. Implements S1b and owner-requested device/session details with optional location sharing. OpenAPI0.3.8 and migration013 add display metadata; credentials and authentication still follow ADR0005. The active account alone can list/revoke its sessions. The mobile entry points are You → Account → Change password / Your devices. Preview routes explain that real accounts are required.

## Sessions and metadata

Each successful new login creates a separate random public handle, never the JWT sid or a hardware identifier. Android reports manufacturer/model, OS release and installed app version through a native method channel after authentication, then sends a guarded current-session metadata update. Login never waits for native metadata. Optional headers from other clients are bounded and ignored if malformed. Missing native metadata does not prevent login. Older active sessions are backfilled without changing credentials and show Unknown device until updated from that device. Their initial recorded timestamp comes from the surviving live refresh credential; historical original login time/model/location cannot be reconstructed retrospectively. New logins record their actual creation time. Opening Your devices refreshes current-device metadata independently of the security controls.

The backend records the connection address and login time. Authenticated activity updates last-seen/IP at most once per minute. Untrusted forwarding headers are ignored; shared hosting proxies/VPNs can affect the observed address. Device and location labels are client-reported, not verified hardware/location identities. Only active, unexpired sessions appear, one row per login despite refresh rotations. Lists are bounded/paginated. Raw JWT session ids, refresh hashes, bearer/FCM tokens, hardware identifiers and raw user agents never leave these endpoints.

Location is explicit and optional: choose Add/Update location, read the explanation, then allow foreground location if needed. Low-accuracy one-shot coordinates go to the device geocoder; only a city/region/country label and update timestamp reach CIRCLE. No background tracking or coordinates are stored by CIRCLE. Remove location clears the current session's label and timestamp. The API rejects coordinate/unknown fields; other sessions cannot be edited. No IP geolocation service or unconsented location inference is introduced. A missing permission/service/geocoder is recoverable and does not block session logout.

DELETE /me/sessions/{sessionId} locks the authenticated user first, rechecks the caller's open session, resolves only its own public handle and atomically revokes all target refresh rows/device registrations. Its access tokens then fail normal middleware checks and queued push cannot pass worker session/device reauthorization. Missing/non-owned handles share404; repeated revocation of an owned handle is idempotent. Password change, refresh, login, current logout and remote revocation share user-first locking. Current-session logout triggers scoped local cleanup. Other accounts, memberships and sessions are untouched; already delivered content/in-flight operations cannot be recalled.

Metadata is privately retained with the account and omitted from active-session lists after revocation/expiry. This is an active-device control screen, not a public device or location directory. A remote phone clears its local view on its next authenticated check; no remote filesystem deletion is claimed.

## Password and local cleanup

Current/new/confirm fields preserve raw strings, support password managers and require a different15–128-character new password. The form explains all-device sign-out. Only an explicit sign_in_required:true response establishes success. The mutation has a per-request no-refresh/no-replay flag while preserving API/account/session guards. Network/5xx/malformed ambiguous outcomes clear secret inputs, disable resubmission and offer local sign-out/sign-in guidance; no automatic mutation retry occurs. Current-password errors remain recoverable. The legacy registration6-character minimum is unchanged; policy alignment remains separate.

Success invalidates optional push, clears private image caches, invalidates draft leases and queues scoped draft deletion independently of token-storage/push failures. ServerSession drops account state and guards cleanup by API/account/session revision so a late request cannot clear a newer same-account login. Automatic session expiry also clears old private drafts. Normal logout completes local cleanup even when flushing pending deletes or optional infrastructure fails. Storage failures cannot preserve in-memory authentication; server-revoked credentials cannot authenticate after restart. No new password/session security push is sent through credentials just revoked; an independent recovery/security-alert channel remains future work.
