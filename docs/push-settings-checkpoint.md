# Notification settings and foreground presentation — N1c2

Source checkpoint, 27 October 2026. The client flag `CIRCLE_PUSH_ENABLED` defaults false and the live installation APK remains 1.0.7+8. This batch does not enable production push or publish an APK.

## Implemented scope

The gated Android server settings screen persists owner-only notification choices through the existing API. It exposes only New Memories and Comments/replies, account-wide enable/disable, quiet hours, searchable IANA time zones and an explicit device-zone action. Unsupported Chats, Events and other categories are not advertised. An explanation sheet precedes any permission request; cancel, ordinary preference changes and passive restoration do not prompt. Denied permission, failed writes and unavailable phone settings produce calm feedback. Firebase remains optional and does not block authentication.

Time zones use the bundled timezone database, including daylight saving. A small Android method channel reads the device zone and opens app notification settings; missing channel/unsupported zone falls back to manual selection. It does not enable server PHP extensions or OS permissions automatically.

A bounded encrypted pending ledger stages validated envelope metadata before handing it to a presenter. Delivered history is written only after successful display/navigation or a permanent content denial. No listener, transient network errors and failed UI handoffs retain pending metadata for a later foreground pump. It holds at most 64 pending entries within the 512-entry total budget, prunes expired/foreign-session entries, and fails closed on storage corruption/capacity errors. This is a single foreground coordinator, not a cross-isolate atomic queue or an exactly-once delivery guarantee.

The foreground host re-fetches preferences and authorized content through the configured API, validates the returned group/Memory/comment references, and displays generic in-app banners without private text. View rechecks authorization and routes to a generated internal Memory path. Payload URLs never choose credential destinations. Pause/account changes dispose presentation; delayed preference responses cannot reconnect while paused, and stale callbacks cannot display/navigate for another session. Quiet-hour pending items are reconsidered on a later foreground pump, not an OS scheduled alarm.

Authenticated requests now carry a login generation through dispatch and refresh/retry. Device registration/unregistration and logout additionally supply the captured generation. Account guards reject old preference/profile requests before dispatch. Stale refresh results cannot overwrite a later login, metadata updates preserve credentials, and serialized token-store writes preserve ordering. Session clearing checks the expected generation atomically and suppresses late callbacks after a newer login. These regressions establish local client behavior, not production authorization proof.
