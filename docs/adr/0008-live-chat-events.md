# ADR 0008: live conversations and Events on shared PHP hosting

28 October 2026. Implements the owner's request to complete Chats and Events on the current main, preserving the recent visual changes. OpenAPI0.4.0 describes the live services; migration017–020 are additive.

ADR0003's WebSocket consequence is deferred because no long-running service is provisioned on this host. Active chat polls authenticated REST every15 seconds and supports manual refresh. Polling/retries pause when the app is inactive. Messages are encrypted in transit and privately stored, not end-to-end encrypted. No instant-delivery or E2E claim.

Group conversations mirror exact membership. Removal and sends/edits serialize under the group lock. A global message-version cutoff preserves earlier text, even if someone edits or unsends it later. Removed people receive no later messages and cannot send/react; rejoining restores current history. Frozen reads omit changing reaction metadata. Sender client ids make retries idempotent; reply/read ids cannot escape a conversation.

Direct conversations require shared exact active membership, current recipient policy and mutual block checks. First contact sends one introduction and waits for recipient acceptance. Loss of shared membership, a block, decline or recipient policy can stop sending; existing private history remains readable to its two participants. No global contact directory, phone-number reachability or automatic consent. Private selected-message reports go to the operator queue, never a shared-group queue. Reporting shares only the selected message and optional note after explicit explanation; it does not export the conversation. Server operators use the private CLI documented in live-chat-events.md.

A device-local encrypted outbox retains the original send id through connection failures. It is isolated by API/account/JWT session and capped at50 intents. Transient failures retry while Chats is active; rejected intents require review. Logout invalidates the old scope and deletes its initialized queue independently of push. App restarts under the same session preserve pending sends; a new login cannot replay old-session intents.

Events store UTC instants plus an IANA zone. Exact-group policy determines creation; organizers/admins edit with version checks. A group/event lock serializes capacity, guests, RSVP deadlines and cancellation. Generic push covers creation, material edits, cancellation, relevant organizer RSVP changes and one-hour reminders. Old versions cancel; the existing worker scans due events in bounded, fair batches so newly registered devices and current members are included. Preferences, quiet hours, membership/session checks and expiry remain authoritative.

Separate liveChat/liveEvents capabilities enable only implemented screens. Photo attachments/covers, content forwarding/sharing, activity indicators, chat search, date polls, cohosts and event albums remain separate extensions; their rich preview screens remain isolated. Existing independent Memories, reports and direct-contact blocking are preserved. Native installation/FCM delivery require physical-device acceptance.
